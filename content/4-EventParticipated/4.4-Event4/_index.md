# DevOps Workshop on AWS

**Date & Time:** 8:30AM – 5PM Monday, November 17, 2025
**Location:** 26th Floor, Bitexco Financial Tower, HCMC

## **Event Objectives**

* Provide comprehensive knowledge and hands-on experience with **AWS DevOps services**.  
* Introduce and practice core DevOps components including **CI/CD, Infrastructure as Code (IaC), container services, and monitoring & observability**.  
* Help participants understand **DevOps culture, principles, and best practices**.  
* Guide attendees on how to **practically implement DevOps processes on AWS**.


## **Program Structure & Main Content**

### **DevOps Overview on AWS**

  * **AWS Certified DevOps Engineer – Professional**

#### **Next Steps**

* Learning resources

## **Key Highlights**

* **CI/CD Pipeline**  
  * AWS CodePipeline provides an end-to-end solution to automate software delivery from source to production.

* **Infrastructure as Code (IaC)**  
  * Both CloudFormation and AWS CDK offer powerful infrastructure management capabilities.  
  * **AWS CDK provides a better developer experience** by using familiar programming languages.

* **Container Services**  
  * AWS offers multiple container options:
    * **Amazon ECS**
    * **Amazon EKS**
    * **AWS App Runner**  
  * Suitable for different use cases, complexity levels, and operational needs.

* **Observability**  
  * **Amazon CloudWatch** and **AWS X-Ray** together deliver comprehensive:
    * Monitoring  
    * Logging  
    * Distributed tracing  

* **DevOps Culture**  
  * DevOps success requires **cultural transformation**, not just tools and technology.

* **Best Practices**  
  * Feature flags  
  * Automated testing  
  * Incident management  


## **What I Learned**

* **DevOps is Culture First**  
  * Tools matter, but **mindset and collaboration** are the real foundation of DevOps success.

* **CI/CD Automation**  
  * Automating the entire delivery pipeline significantly improves release speed and system reliability.

* **Benefits of IaC**  
  * Version-controlled infrastructure  
  * Repeatability and consistency  
  * Faster and safer infrastructure changes

* **Container Strategy**  
  * Selecting the right container service depends on:
    * System complexity  
    * Team expertise  
    * Operational requirements

* **Observability Matters**  
  * Robust monitoring and tracing are essential for maintaining reliable systems.


## **Applications to Work**

* **Implement CI/CD**  
  * Use AWS CodePipeline for automated deployments in current projects.

* **Adopt IaC**  
  * Begin managing infrastructure with CloudFormation or AWS CDK.

* **Container Migration**  
  * Identify opportunities to containerize existing applications.

* **Improve Monitoring**  
  * Enhance CloudWatch dashboards and alarms for better system visibility.

* **DevOps Practices**  
  * Apply DevOps principles and best practices in day-to-day work.


## **Event Experience**

Before attending the workshop, I thought DevOps was mainly about tools like Docker or Jenkins.  
This session helped me gain a deeper understanding of **“DevOps Culture.”**

* Successfully building a **fully automated CI/CD pipeline from code commit to production deployment** was extremely satisfying and highlighted how much repetitive work can be eliminated.  
* The **Observability session with AWS X-Ray** was especially impressive—like having “X-ray vision” into the application, clearly identifying where requests slow down.  
* Hands-on labs helped remove my fear of “deploying,” as everything is now controlled, repeatable, and automated.


## **Key Takeaways**

* **Automation is Key**  
  * Any task performed manually more than twice should be automated.  
  * CI/CD not only accelerates delivery but also minimizes human error.

* **DevOps is a Shared Responsibility**  
  * CI/CD and monitoring are not just for DevOps engineers.  
  * As a developer, understanding these processes helps in writing code that is easier to deploy and debug.

* **Measure Everything**  
  * You cannot improve what you cannot measure.  
  * Proper monitoring and logging must be set up from the very beginning.
